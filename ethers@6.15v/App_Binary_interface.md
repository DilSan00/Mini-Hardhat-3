## 🛠️ Ethers.js API: Низкоуровневые Механизмы

Эта часть API Ethers.js занимается сложными задачами **кодирования и декодирования** данных между читаемым форматом JavaScript и бинарным форматом EVM (ABI).

### 1. Application Binary Interface (ABI)

**ABI** — это "словарь" и "правила" контракта. Он описывает, как кодировать аргументы функций, декодировать результаты, события и ошибки.

#### Класс `Interface`

Это центральный низкоуровневый класс, который абстрагирует детали кодирования/декодирования.

| Функция/Метод | Назначение (Что делает) |
| :--- | :--- |
| `new Interface(fragments)` | Создает экземпляр, принимая ABI в любом формате (JSON, Human-Readable, Array of Fragments). |
| `interface.encodeFunctionData(...)` | **Кодирует** вызов функции (включая аргументы) в бинарный `tx.data` для транзакции. |
| `interface.decodeFunctionData(...)` | **Декодирует** бинарные данные (`tx.data`) обратно в читаемый список аргументов функции. |
| `interface.parseLog(log)` | **Парсит** бинарный лог (из квитанции) для определения события и извлечения аргументов. |
| `interface.parseError(data)` | **Парсит** данные, возвращенные при **revert** (откате), чтобы определить ошибку и её аргументы. |
| `interface.formatJson()` | Возвращает ABI в стандартном **JSON-формате** (как выдает Solidity). |

### 2. Результаты и Ошибки (`Result`, `checkResultErrors`)

#### Класс `Result`

`Result` — это специальный подкласс `Array`, который используется для возвращаемых значений из функций контрактов или аргументов событий.

* **Доступ:** Позволяет получать значения как **по индексу** (как обычный массив), так и **по имени** (если имена параметров есть в ABI).
* **Конвертация:** Методы `result.toArray()` и `result.toObject()` позволяют преобразовать его в стандартные типы JavaScript (при этом **отложенные ошибки** могут быть выброшены).

#### Отложенные Ошибки (`checkResultErrors`)

Hardhat Ignition может **откладывать ошибки** (deferred errors) декодирования, если они не влияют на общую возможность парсинга данных.

* **Назначение:** Если некорректная строка в событии никогда не используется в коде, она не прерывает программу.
* **Проверка:** Функция `checkResultErrors(result)` позволяет принудительно проверить `Result` на наличие отложенных ошибок.

### 3. Типизированные Значения (`Typed`)

**`Typed`** — это механизм, который явно сообщает Ethers.js, какой тип Solidity должен быть у данного значения JavaScript, поскольку JavaScript не имеет такого точного соответствия (например, `45` может быть `uint8` или `uint256`).

* **Назначение:** Обеспечивает прозрачное взаимодействие с контрактами, особенно в неоднозначных случаях (например, при вызове `getFunction` или `getError`).
* **Создание:** `Typed` создается с помощью статических методов для каждого типа Solidity:
    * `Typed.address("0x...")`
    * `Typed.uint256(100n)` или просто `Typed.uint(100n)`
    * `Typed.bytes32("0x...")`
    * `Typed.tuple([v1, v2])`
* **Свойства:** Имеет свойства `typed.type` (тип Solidity, напр., `"uint256"`) и `typed.value` (фактическое значение).

#### Класс `Indexed` (для Событий)

* Используется внутри **логов событий** в тех случаях, когда индексированный параметр события не является типом фиксированной длины (например, `bytes`, `string`, массивы).
* Вместо самого значения в лог записывается его **хеш (`keccak256`)**. Класс `Indexed` представляет этот хеш.
