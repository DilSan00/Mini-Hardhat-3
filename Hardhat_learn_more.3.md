## ✨ Что нового в Hardhat 3

Hardhat 3 — это крупное обновление, ориентированное на скорость, гибкость и поддержку современных стандартов.

### 🔬 Тестирование

  * **Поддержка Solidity-тестов (Foundry-compatible):** Hardhat 3 теперь поддерживает быстрые, низкоуровневые тесты, написанные на Solidity (включая **fuzz** и **invariant tests**).
      * **Файлы:** Тестовые контракты должны быть в файлах `.t.sol` (в `contracts/`) или в любом файле в `test/`.
      * **Запуск:** Используйте `npx hardhat test solidity` для запуска тестов на Solidity или `npx hardhat test` для запуска всех тестов.
  * **Code Coverage:** Встроенная поддержка **покрытия кода** (Solidity и TypeScript) работает "из коробки" с флагом `--coverage`.

### 🌐 Сети и Конфигурация

  * **Multichain Support:** Снято ограничение на симуляцию только Ethereum Mainnet. Теперь можно симулировать **разные типы сетей** (например, OP Mainnet) и настраивать несколько симулированных сетей одновременно.
  * **Network Manager:** Улучшено управление сетевыми подключениями. Теперь задачи могут создавать и использовать **несколько подключений** одновременно.
  * **Viem — Рекомендованная Библиотека:** **Viem** (современная, типобезопасная библиотека) официально рекомендована и интегрирована через плагин `hardhat-viem` для взаимодействия с контрактами.
      * **Типобезопасность:** Автоматически генерирует **TypeScript-типы** для контрактов (`Typed artifacts`).

### ⚙️ Управление и Секреты

  * **ESM-first:** Hardhat 3 использует **ECMAScript Modules (ESM)** по умолчанию (современный стандарт JavaScript).
  * **Конфигурационные Переменные (`Config Variables`):** Позволяют откладывать загрузку значений (lazy loading) до момента, когда они действительно нужны.
  * **Менеджер Секретов (`hardhat-keystore`):** Позволяет безопасно хранить конфиденциальные данные (**приватные ключи, API ключи**) в **зашифрованном файле** вместо того, чтобы использовать небезопасные переменные окружения.
      * **Использование:** Значение переменной задается через `configVariable("KEY_NAME")`.
      * **Хранение:** `npx hardhat keystore set KEY_NAME`
  * **Декларативная Конфигурация:** Вся конфигурация стала полностью декларативной, что упрощает управление проектом.

## 🔒 Верификация Контрактов

**Плагин `hardhat-verify`** используется для подтверждения того, что код контракта соответствует развернутому байткоду (например, на Etherscan).

1.  **Настройка:** Добавьте `apiKey` Etherscan в конфиг `verify`.
2.  **Верификация:**
    ```bash
    npx hardhat verify --network <сеть> 0x...
    ```
      * Вы можете передать аргументы конструктора через CLI или с помощью файла (`--constructor-args-path`).
      * **Hardhat Ignition** автоматически верифицирует контракты при использовании флага `--verify` во время деплоя.

## 🔧 Кастомизация Компилятора

Вы можете полностью настроить компиляцию Solidity в `hardhat.config.ts` в блоке `solidity`.

| Настройка | Что делает |
| :--- | :--- |
| `version` | Установка версии `solc`. |
| `compilers` | Использование **нескольких версий** `solc` для разных файлов. |
| `overrides` | Переопределение настроек (например, оптимизатора) **для конкретного файла**. |
| `npmFilesToBuild` | Включение в компиляцию контрактов, находящихся **в npm-зависимостях**. |

## 📌 Основные Команды Hardhat 3

| Команда | Назначение |
| :--- | :--- |
| `npx hardhat --init` | Инициализация нового проекта. |
| `npx hardhat build` | Компиляция контрактов. |
| `npx hardhat test` | Запуск всех тестов (Solidity и TypeScript). |
| `npx hardhat run <script.ts>` | Выполнение скрипта. |
| `npx hardhat keystore set <KEY>`| Зашифрованное хранение секрета. |
| `npx hardhat verify ...` | Верификация развернутого контракта. |
